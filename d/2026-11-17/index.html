什么是 Harness？先看清它与 Agent 的关系

Agent
你交给它目标，它会用工具、看结果、接着做的 AI 助手。
Harness
让助手运转的支撑软件，负责接工具、传结果，也可以管进度和权限。

一个是整套助手，一个是其中的支撑。Harness 通常就在 Agent 里面。

约 10 分钟，拆开一个 AI 助手的工作过程。

Agent 是整套助手，Harness 在它里面

先想象一位办事员。你交给他一个目标，他要理解你的意思、使用手边的工具，再根据结果调整做法。Agent（常译作「智能体」）就像这样的 AI 助手，能围绕目标连续做事。

这套助手里，AI 模型负责读懂信息、作出判断。你可以先把模型理解为处理语言、提出下一步的核心能力。Harness是围绕模型运行的一套软件，负责把信息送进去、安排工具执行，再把结果带回来。

所以，谈 Agent 时，通常在看「这个助手能帮我完成什么」。谈 Harness 时，在看「这个助手背后的工作过程怎样组织」。一个能实际运行的 Agent，通常已经包含模型、Harness 和所接入的工具。

为什么光会回答还不够？

让 AI 帮你找资料，它可以写出「接下来搜索最新价格」。要真的搜到价格，还得有程序去执行搜索，并把搜到的内容交回来。

这里的工具，就是能执行具体动作的软件功能，比如查网页、读文件、发邮件。Harness 把模型提出的动作连接到工具。模型拿到工具的结果，再判断下一步。这种来回配合，才让 Agent 能连续推进任务。

Harness 怎样帮 Agent 接着做？

长任务往往要分很多轮。AI 模型每次能同时处理的信息有限，这个范围叫上下文窗口，可以理解成眼前能摊开的资料。工作时间长了，旧内容可能放不下，下一轮也可能拿不到完整经过。

Harness 可以安排保存进度，并在继续工作时提供相关记录。比如帮你整理一批文件，交接记录写明哪些已经处理、哪些还需要检查，Agent 就更容易接着做。

这解释了 Agent 为什么有时能「记住进度」。这份能力往往来自模型与 Harness 的配合。保存什么、何时重新提供、记录是否准确，都影响接续效果。

谁决定 Agent 能做到哪一步？

让 Agent 整理邮件和让它发出邮件，后果不同。用户或开发者可以设定权限，例如允许读邮件、允许写草稿，发送之前必须确认。

Harness 可以在动作交给工具之前执行这些限制。写一句「请谨慎发送」是在提醒模型；在系统里设置发送权限，则能让动作真的停下来等待授权。具体能限制什么，要看产品怎样实现。

Agent 可以提出行动，Harness 可以按配置约束行动。它遵守的规则由人和产品设定，实际权限检查还可能由工具服务共同执行。

怎样判断 Agent 真的完成了？

AI 能写出听起来很确定的回答。执行任务时，还需要查看真实结果。例如发送邮件后，要看发送记录；修改表格后，要打开文件检查改动是否正确。

Harness 可以收集工具回报，并安排下一步检查。有些检查由 AI 阅读结果完成，有些由写好的程序自动完成。检查得到的证据，帮助 Agent 决定继续修正、向你求助，还是报告完成。

Harness 帮 Agent 获得反馈。检查设计得是否充分、反馈是否可信，决定了「完成」这句话有多可靠。

为什么这两年 Harness 被反复提起？

当 AI 被要求处理更长、更复杂的任务，能力的短板会出现在整个办事过程里。模型可能判断得不错，但找不到资料、接不上工具、丢失进度，最后仍然交不出结果。

2025 年，Anthropic 分享了让编程 Agent 留下进度记录、在下一轮继续工作的实践。2026 年，OpenAI 讨论了如何通过清晰的环境、资料和检查机制帮助 Agent 完成软件工作。

这些实践让 Harness 受到更多关注。模型提供判断能力，围绕它的运行安排影响这种能力能否稳定发挥。不同团队使用 Harness 一词时，覆盖范围会有差异，有的偏重运行循环，有的还包含更广的工作环境和规则。

换个 Harness，Agent 就会更聪明吗？

同一个模型，放进不同的系统，使用体验可能很不一样。有的 Agent 能读取你提供的文件、保存工作进度、检查结果；有的只拿到了当前一句话。给模型的信息和可执行动作不同，最终表现也会不同。

更合适的 Harness 能减少漏步骤和重复劳动，但模型仍可能理解错需求，工具也可能返回错误信息。Harness 无法凭空补出未接入的资料，也无法保证所有判断正确。

此外，多轮检查和重试会花时间，也可能增加费用。保存记录、维护工具、设计权限同样需要投入。任务很简单时，整套复杂流程未必值得。

它与提示词、固定流程有什么关系？

提示词就是你给 AI 的要求，例如「先查资料，再写总结」。Harness 可以把这些要求交给模型，也可以把部分要求落实为可执行的检查和限制。

固定流程会预先规定每一步怎样走。Agent 则可以让模型根据中途结果选择下一步。真实产品经常把两种方式结合起来，例如查询过程由 AI 调整，提交付款必须经过固定的确认步骤。

Harness 为这些安排提供运行支持。它能承载固定规则，也能支持模型灵活判断。仅凭产品用了这个名称，无法判断它开放了哪些能力。

下次看到这两个词，问什么最有用？

看到「Agent」，先问它能替你完成什么任务，以及遇到变化时能否调整做法。看到「Harness」，再看它怎样接工具、保存进度、执行权限和检查结果。

如果你要选一个帮忙处理文件的助手，可以实际试一件小事。让它处理几份资料，中途暂停后再继续，检查它有没有漏项，最后打开结果文件看看。这样能看到整套 Agent 的实际表现。

Agent 是你交任务的整套助手。Harness 是让这套助手运转的支撑软件。前者描述办事能力，后者解释这种能力背后的组织方式。
