AI 工具 · Skill（技能）

Skill 不是让 AI 变聪明，是给它一本岗位说明书

你在 WorkBuddy、Qoder 这类工具里，会看到「安装一个 Skill」。它听着像给 AI 升级大脑，其实更准确的说法是：给 AI 放一本写得清清楚楚的岗位说明书。说明书里写明「什么时候翻开我、按哪几步做、哪些事不能做」。AI 本身没有变聪明，但它办事开始有章法。

0WorkBuddy 安装方式：市场、链接、手动上传
0代码也能用——从市场一键安装即可

01

一句人话：Skill 是什么

想象你公司来了一个新员工。他很聪明，但他不知道你们的报销流程、不知道你们的客户名单格式、不知道你们周报要写哪几栏。你怎么办？

你会给他一本岗位说明书：什么时候用、按哪几步做、做完交什么格式。他不用变聪明，只是多了一本可以翻的手册。

Skill 就是这本手册。官方定义是「一个包含指令、脚本和资源的文件夹」，核心文件叫 SKILL.md。AI 遇到相关任务时，会翻开这本手册，按里面写的步骤来做。

拖一下滑杆，看「没有手册」和「有手册」的区别：

判断标准不是 AI 说话多聪明，而是重复做同一件事时，步骤会不会漏、格式会不会乱。Skill 解决的就是这个问题。
02

为什么需要 Skill：AI 的「记忆」像沙子

大模型（就是 ChatGPT、Claude 这类 AI 的底层技术）有一个根本局限：对话结束后，模型本身不会自动把你刚教过的流程变成长期能力。有些工具另有记忆功能，但记忆更像零散笔记；Skill 解决的是另一件事——把一套完整流程固定下来，反复使用。

你可以每次重新解释，但这有三个问题：

  • 费时间：每次都要把规则说一遍，说漏了就出错。
  • 不一致：你今天的说法和昨天的说法可能有细微差别，AI 就会给出不同结果。
  • 不可复用：你教会了 AI，同事还得再教一遍。

Skill 的解法是：把规则写成一个文件，放在 AI 能找到的地方。每次遇到相关任务，AI 自动翻开这个文件，按里面写的来做。你不用重新教，同事也能直接用同一本手册。

Skill 不改变 AI 的「大脑」（模型权重），它只是给 AI 一个可以随时查阅的外部参考。就像你不需要让新员工变聪明，只需要给他一本手册。
03

它长什么样：一个文件夹

一个 Skill 就是一个普通文件夹。打开它，你会看到这些东西：

SKILL.md 长什么样

这是 Skill 的核心文件。它用 Markdown（一种简单的文本格式）写成，开头有一段「元数据」，告诉 AI 这个 Skill 叫什么、什么时候该用它：

--- name: invoice-helper description: 当用户要整理发票或报销单时使用。 检查附件是否齐全，统一填入固定表格。 --- # 整理报销单 1. 先确认日期范围和币种。 2. 把每张发票的日期、金额、用途填入表格。 3. 缺附件时不要猜测，单独列出「待补项」。 4. 输出格式：Excel 表格，列名固定。

上面是一个简化示例。真实的 SKILL.md 可以更复杂，但核心结构就是这样：开头写「我是谁、什么时候用我」，正文写「按这几步做」。

不是每个 Skill 都必须有 scripts/、references/、assets/ 这三个文件夹。SKILL.md 才是唯一必须的文件，其他都是可选的辅助。
04

AI 怎么找到它：渐进式披露

你可能装了几十个 Skill。AI 不会每次都把所有手册全部读一遍——那太慢了，也会占用它的「工作记忆」。

它用的是渐进式披露（Progressive Disclosure）：分三步，按需加载。

这个机制有一个重要后果：description 写得好不好，直接决定 AI 能不能找到你的 Skill。如果 description 写得太模糊（比如「处理文档」），AI 可能在该用的时候找不到它；写得太窄（比如「只处理 2024 年 3 月的发票」），AI 可能在不该用的时候误用它。

渐进式披露是 Anthropic 在 2025 年 10 月发布 Agent Skills 时提出的核心设计。它的目的是：让 AI 在需要时才加载详细信息，而不是一开始就把所有手册塞进脑子里。
05

Skill、Prompt、MCP 有什么不同

这三个词经常一起出现，很容易混。用一句话区分：

PromptSkillMCP

就像你口头告诉新员工「这次记得用 A4 纸打印」。说完就过去了，下次还得再说一遍。

Prompt 随对话消失；Skill 是一个持久文件，随时可以翻开；MCP 是一个运行中的服务，提供外部能力。

Prompt 直接打字就行；Skill 要放到指定目录或从市场安装；MCP 要配置连接参数。

Prompt 是临时指令；Skill 是持久流程；MCP 是能力扩展——三者可以配合使用，不互相替代。

Anthropic 官方说法：Skill 和 MCP 是互补关系。MCP 让 AI 能连接到外部工具（比如数据库、邮件系统），Skill 告诉 AI 连上之后该怎么用这些工具完成一个完整流程。
06

WorkBuddy：怎么安装 Skill

WorkBuddy 是腾讯出品的 AI 办公工作台。它有一个技能市场，里面汇集了大量现成的 Skill，不需要自己写代码。

安装方式有三种，点下面的按钮看每种方式的流程：

三种方式的区别

  • 技能市场：最简单。在 WorkBuddy 左侧导航点「扩展 → 技能」，浏览或搜索，找到后点「安装」即可。适合大多数人。
  • 发链接：把 GitHub 等平台的 Skill 仓库链接发给 WorkBuddy，告诉它「帮我安装这个」。它会自动下载、放置、加载。适合从社区获取 Skill。
  • 手动上传：已经有写好的 SKILL.md 文件（比如同事发给你的），在「扩展 → 技能」里点「安装技能」，直接上传文件。上传后自动识别并加载。
WorkBuddy 官方文档还提到两种进阶方式：「查找技能」（描述你想做的事，让它自动找合适的 Skill）和「创建技能」（描述你想做的事，让它帮你生成一个 Skill）。这两种适合有明确需求但找不到现成 Skill 的场景。

装完之后：关闭和卸载

官方对 Skill 的定义是：把脚本、工作流程封装起来，用来扩展 WorkBuddy 的能力。装了之后在授权范围内，它可以替你发邮件、读写文件、查询信息。所以管理入口也给了两个：

  • 关闭：暂停这个 Skill 被调用，文件还在。关闭状态在多设备之间同步。
  • 卸载：直接删掉，之后要用得重新安装。

暂时不想用某个 Skill 又不想重装，选「关闭」就够了。

07

WorkBuddy：怎么使用 Skill

安装完成后，有三种方式让 WorkBuddy 使用 Skill：

每种方式的细节

  • 自动触发：你直接描述需求，WorkBuddy 自动判断有没有匹配的 Skill 并启用。比如你装了「简历优化」Skill，然后说「帮我根据岗位 JD 优化简历」，它会自动调用。
    这是最自然的方式，但依赖 description 写得够清楚。
  • / 快捷调用：在输入框打 /，会弹出已安装的 Skill 列表，选一个就行。
    适合你明确知道要用哪个 Skill 的时候。
  • 对话中指名：直接在对话里写「使用 xxx Skill 来做这件事」。
    适合复杂指令，或者你想同时指定 Skill 和具体参数的时候。
注意：@ 在 WorkBuddy 里是添加上下文（比如附上一个文件），不是调用 Skill。别搞混了。
08

Qoder / QoderWork：怎么使用 Skill

Qoder 和 QoderWork 也支持 Skill，机制和 WorkBuddy 类似，但目录和触发方式有自己的约定。

QoderWork 的 Skill 存放在 ~/.qoderwork/skills/ 目录下。使用方式和 WorkBuddy 类似：

  • 自动触发：直接描述需求，QoderWork 自动判断是否有匹配的 Skill。
  • / 调用：输入 / 弹出已安装 Skill 列表。
  • 指名调用：在对话中直接写「使用 xxx Skill」。
  • @ 是上下文：@ 用于添加文件/文件夹等上下文，不是调用 Skill。

安装方式：Skill 广场浏览、从开源社区获取（发链接让它自动下载）、手动上传本地文件。

Qoder CLI 的 Skill 有两个存放位置：

  • 用户级：~/.qoder/skills/（国内版：~/.qoder-cn/skills/）——所有项目都能用。
  • 项目级：.qoder/skills/（放在项目根目录下）——只有这个项目能用。

触发方式：模型根据你的请求和 Skill 的 description 自主决定是否调用；你也可以用 /skill-name 手动触发。

Qoder CLI 官方文档提到：Skill 的执行「视能力而定，可能需要授权」——也就是说，涉及文件操作、网络请求等敏感动作时，会先问你。

如果你之前用 WorkBuddy，Qoder 支持一次性导入：

  • 可导入：任务记录、定时任务、记忆、可迁移的 Skill、MCP 连接器、插件。
  • 不导入：项目代码、API Key。
  • 被跳过的 Skill 会单独列出名称和来源目录，方便你手动处理。

注意：这是单次导入，不是持续同步。导入后两边各自独立。

不想从零写？WorkBuddy 官方支持「用一句话描述需求」直接生成 Skill，也支持让它先帮你找有没有现成的。Qoder 侧同样提供了创建 Skill 的辅助入口（具体名称以你手头工具的界面为准）。适合想自己写但不知道从哪儿开始的人。
09

Skill 能做什么，不能做什么

很多人对 Skill 有两个极端误解：要么觉得它无所不能，要么觉得它只是个花哨的提示词。实际情况在中间。

能做的

  • 固定流程：把「整理发票」「写周报」「优化简历」这类重复性工作的步骤写清楚，AI 每次按同一套来做。
  • 调用脚本：Skill 文件夹里可以放小程序（scripts/），AI 在需要时运行它们，完成计算、格式转换等固定操作。
  • 引用资料：references/ 里可以放模板、规范、字段说明，AI 在需要时查阅，不用你每次重新贴。
  • 跨对话复用：写一次，以后每次新对话都能用，不用重新教。

不能做的

  • 不能让 AI 变聪明：Skill 不改变模型本身。如果 AI 本来就不会做某件事（比如理解你们公司特有的行业黑话），Skill 也帮不了。
  • 不能保证结果正确：Skill 只是告诉 AI 「按这几步做」，但 AI 仍然可能在某一步出错。你仍然需要检查输出。
  • 不能替代 MCP：如果 AI 需要连接到外部系统（比如你的邮件、数据库），那是 MCP 的工作，不是 Skill 的。
  • 不能自动更新：Skill 是静态文件。如果流程变了，你得手动改 SKILL.md，AI 不会自己更新。
一句话总结：Skill 让 AI 做事更稳定、更可复用，但不让它变得更聪明、更准确。你仍然需要检查输出，仍然需要为结果负责。
10

安全风险：第三方 Skill 要小心

Skill 本质上是一段会被 AI 执行的指令。如果这段指令来自不可信的来源，它可能做你不想让它做的事。

WorkBuddy 官方的安全建议

WorkBuddy 官方文档明确列出了三条：

1

优先使用官方推荐的 Skill

技能市场里标有「官方推荐」的 Skill，由平台方挑选上架，风险相对更低。来源不明的社区 Skill 质量参差不齐，需要你自己判断。

2

注意数据流向

部分 Skill 会将你的输入发送到第三方服务。在使用前，先看清楚它的 description 和 scripts/ 里有没有网络请求。

3

非官方 Skill 可能存在恶意行为

官方文档原话：非官方 Skill 可能存在「恶意提示词注入、越权访问、后门程序」等隐患。安装前最好先看一遍 SKILL.md 的内容。

这不是吓唬你。Skill 的门槛很低——任何人都可以写一个 SKILL.md 文件并发布。就像手机 App 一样，来源不明的 Skill 不要随便装。装之前花两分钟看一下它的内容，是值得的。
11

自己写一个最小的 Skill

如果你有一个反复要做的任务，而且现有 Skill 都不完全符合你的需求，你可以自己写一个。最小的 Skill 只需要一个文件。

第一步：创建文件夹

在对应工具的 Skill 目录下新建一个文件夹，名字用小写英文和连字符：

# QoderWork（桌面版） ~/.qoderwork/skills/my-weekly-report/ # Qoder CLI · 用户级（所有项目可用） ~/.qoder/skills/my-weekly-report/ # Qoder CLI · 项目级（只在这个项目可用） 你的项目目录/.qoder/skills/my-weekly-report/

WorkBuddy 这边不用手动建文件夹：写好压缩包后，在技能管理界面选「本地上传」装进去就行。

第二步：写 SKILL.md

在文件夹里创建 SKILL.md，按这个模板写：

--- name: my-weekly-report description: 当用户要写周报时使用。 按「本周完成/下周计划/需要协调」三栏整理， 语言简洁，每条不超过两行。 --- # 写周报 1. 先问用户：这周做了哪些事？ 2. 把用户说的内容分成三类： - 本周完成 - 下周计划 - 需要协调的事项 3. 每条用一句话概括，不超过两行。 4. 输出格式：Markdown 表格。 5. 如果用户没提到「需要协调」，这一栏写「无」。

第三步：测试

保存文件后，回到工具里，用自然语言触发它（比如「帮我写这周的周报」），看 AI 是否按你写的步骤来做。如果不对，改 SKILL.md，再试。

写 Skill 的核心技巧：description 要写清楚「什么时候用」，正文要写清楚「按哪几步做」。不要写「尽量做好」这种模糊指令——AI 需要的是具体步骤，不是鼓励。
12

这跟你有什么关系

不管你是普通上班族、自由职业者，还是团队负责人，Skill 都在改变「用 AI 做事」的方式。挑一个身份看：

  • 你每天重复做的那些事——整理会议纪要、写周报、格式化数据——都可以写成 Skill，让 AI 每次按同一套来做。
  • 你不需要会写代码。从技能市场安装现成的 Skill，或者用「创建技能」功能描述你的需求，让它帮你生成。
  • 最重要的变化：你的经验不再只存在你脑子里。写成 Skill 之后，新同事来了也能直接用同一套流程。
  • 你可以把自己的工作方法论打包成 Skill，形成可复用的个人知识库。换工具时，Skill 可以跟着你走（只要新工具支持同样的格式）。
  • 接单时，你可以把「客户 brief → 初稿 → 修改 → 交付」的流程写成 Skill，每次按同一套来，减少遗漏。
  • 注意：Skill 不能替代你的判断。它只是把你的流程固定下来，但「这个客户的特殊需求怎么处理」仍然需要你来决定。
  • 团队里那些「只有老王知道怎么做」的流程，可以写成 Skill，变成团队共享资产。老王离职了，流程还在。
  • 新人入职时，不用花三天口头交代，直接给他装几个 Skill，他就能按标准流程开始做事。
  • 管理建议：不要一上来就装几十个 Skill。先挑最高频的 3 个流程，写成 Skill，用熟了再扩展。太多闲置 Skill 反而会增加 AI 的选择负担。
Skill 的本质是把人的经验变成机器可读的文档。这件事的价值不在于 AI 变强了，而在于你的知识不再只存在你脑子里——它可以被复制、被分享、被继承。

最后，两个问题

  1. Q1

    你每周重复做的那件事，有没有可能写成一个 Skill？

    想想看：有没有哪个任务，你每次都要跟 AI 重新解释一遍规则？如果有，把那些规则写下来，就是一个 Skill 的雏形。

  2. Q2

    你团队里「只有某个人知道怎么做」的流程，有多少条？

    这些流程如果那个人离职了，会怎样？把它们写成 Skill，不是为了替代人，而是为了让知识不随人走。

没有标准答案。但如果你能列出三条以上「每次都要重新解释」的任务，那你已经找到了写 Skill 的起点。
